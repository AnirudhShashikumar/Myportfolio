18 / MOTION ARCHITECTURE

GSAP and ScrollTrigger coordinate the primary narrative states.

The implementation avoids animation sequences that must finish before the interface becomes correct.

This allows the experience to remain deterministic during:

SLOW SCROLL
FAST SCROLL
REVERSE SCROLL
SCROLLBAR JUMPS
DIRECT ANCHOR NAVIGATION

The system favors normalized timelines and clear transform ownership over large numbers of independent animation triggers.

⸻

19 / PERFORMANCE PHILOSOPHY

A cinematic interface should not feel heavy.

Performance decisions include:

* bounded animation ownership
* restrained WebGL complexity
* capped device-pixel ratio
* visibility-aware rendering
* offscreen rendering reduction
* reduced mobile complexity
* minimal continuous animation
* transform/opacity-focused motion
* cleanup of ScrollTrigger/GSAP contexts
* responsive asset delivery
* deterministic scroll state
* no React state updates per animation frame

The goal is not to remove the interesting parts.

It is to make them cheaper, clearer and more precise.

27 / ENGINEERING PRINCIPLES

A few principles shaped the implementation:

01 — Scroll position is authoritative

The current scroll position determines visual state.

Animation should never need to catch up with the user.

02 — Transform ownership matters

A parent responsible for horizontal movement should not fight a child responsible for vertical storytelling.

03 — Static composition comes first

Every important animation state should still look intentional when frozen.

04 — Mobile deserves its own solution

Complex desktop interactions are simplified when that creates a better touch experience.

05 — Accessibility is architecture

Reduced motion and semantic content are not patches applied after animation.

06 — Evidence beats unsupported claims

Project results, measurements and achievements are presented with their actual context.

07 — Complexity has to earn its place

If an effect does not improve communication, it probably should not exist.
